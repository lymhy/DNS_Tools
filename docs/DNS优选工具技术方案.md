# DNS 优选工具技术方案

> 项目代号：`dnspick`
> 目标：为个人宽带环境快速、客观地找出"最适配当前网络"的 DNS 服务器
> 版本：v1.1 ｜ 2026-10-07

---

## 1. 背景与问题定义

### 1.1 为什么需要"优选"

换 DNS 不是"延迟越低越好"。用户真实感受到的影响来自四个维度：

| 维度 | 说明 | 常见误区 |
|---|---|---|
| **解析延迟** | 发起查询到拿到结果的往返时间 | 只 ping DNS 服务器 IP 不等于查询延迟（ICMP 可能被限速，且不代表 53 端口服务能力） |
| **稳定性** | 超时率、丢包率、结果一致性 | 偶发超时在高峰期才暴露，单次测试发现不了 |
| **干净度** | 是否存在域名劫持、NXDOMAIN 重定向、DNS 污染 | 运营商 DNS 延迟最低但可能有广告劫持 |
| **就近性（核心）** | DNS 返回的 CDN 节点 IP 是否离你的宽带近 | 这是"适配宽带"的关键：境外公共 DNS（如 8.8.8.8）查询延迟可能尚可，但不带 EDNS Client Subnet 时 CDN 调度可能把你调到外省甚至海外节点，下载速度骤降 |

**核心设计理念**：DNS 查询延迟只占上网体验的很小一部分，真正决定体验的是"DNS 帮你选的 CDN 节点好不好"。因此本工具的重点是**端到端验证**——用每个候选 DNS 解析同一批大流量域名，再实际去连接返回的 IP 测 TCP/HTTP 延迟和归属地，而不是只测 DNS 本身的响应速度。

### 1.2 使用场景

- 换宽带/搬家/换路由后，想知道该填哪个 DNS
- 网页打开慢、视频卡顿时，排查是不是 DNS 选得不好
- 定期复测（公共 DNS 的 anycast 节点会调整，结论有时效性）

### 1.3 目标与非目标

**目标**
- 一条命令完成测评：快速模式约 1 分钟（有效样本 8），完整模式数分钟（有效样本 30 + 递归/污染/ECS/TTFB/辅助探测）；实测时长随候选数与网络状况而定，可用 `--samples` 调节
- 自动把当前运营商（DHCP/系统配置）DNS 纳入候选作为基线
- 输出可解释的评分排名 + 推荐主用/备用组合 + 一键应用命令
- 支持自定义候选列表、域名列表、评分权重

**非目标（v1 明确不做）**
- 不做长期大规模拨测平台（仅本地单机）
- 不做 DNS 代理/分流（那是 AdGuard/mosdns 的活）
- 不内置破解或绕过审查功能，污染检测仅用于"告知风险"

### 2.2 测评流水线

```
阶段0 环境自检 → 阶段1 延迟与稳定性 → 阶段2 干净度 → 辅助探测 → 阶段3 就近性与端到端 → 分组评分 → 报告/应用
   (~5s)          (~40s / ~3min)       (~30s)        (DNSSEC/NSID/双栈)     (~90s)
```

各阶段串行执行，**阶段内部对多个 DNS 采用交叉轮询**（每轮依次测每个 DNS 的一次查询，而非测完一个再测下一个），用于平均网络波动，避免"先测的赶上网络好、后测的赶上抖动"。

自 v1.1 起：
- **辅助探测**在阶段2 之后、阶段3 之前执行 DNSSEC 验证、NSID/CHAOS 采集与双栈可用性检测；`--no-aux` 可整体跳过（阈值 `aux_probes: false` 等效）；
- **分组评分**：udp / udp6 / doh / dot 各自排名、各自推荐主备（跨协议延迟不可比，详见 §4.2）；
- **可复现**：抽样（每域名 IP 子集、TTFB 域名子集）统一由 `--seed` 驱动，默认固定种子 `20260101`，同参数两次运行得到同一批抽样；`--seed 0` 为真随机。

## 3. 测评指标体系与测量方法

### 3.1 指标定义

| 指标 | 定义 | 测量方法 | 快速模式 | 完整模式 |
|---|---|---|---|---|
| 缓存延迟 P50/P95 | 命中解析器缓存的查询延迟 | 同一热门域名连查「热身+样本」次（默认热身 2；有效样本 快速 8 / 完整 30，`--samples` 可覆盖），取有效样本的 R-7 线性插值分位数 | ✅ | ✅ |
| 缓存延迟均值 95% CI | 均值的不确定度 | 同一批有效样本的 t 分布 95% 置信区间半宽 `t(n-1,0.975)·s/√n`（n≥31 用 1.96 近似） | ✅ | ✅ |
| 丢包率 | 首次尝试即失败的查询占比 | 阶段1 的「首次尝试」单独记账（`Attempts/FirstFail`）：重试成功仍记 1 次丢包，不被失败重试掩盖 | ✅ | ✅ |
| 递归延迟 P50 | 完整递归解析的延迟 | 随机子域名法（见 3.2 ①） | — | ✅ |
| 成功率 | 查询不超时/无丢包的比例 | 全部查询统计，超时阈值 2s，重试 1 次并单独记账 | ✅ | ✅ |
| NXDOMAIN 劫持 | 对不存在域名返回广告 IP | 查询保证不存在的随机域名，返回 A 记录即劫持 | ✅ | ✅ |
| 解析器透明劫持 | 查 A 却被运营商 53 端口透明代理截胡 | 向目标 DNS 查询 `o-o.myaddr.l.google.com` 的 TXT，回显 IP 是私网/命中运营商解析器（且非自身）即劫持（备用：`whoami.ds.akahelp.net`） | ✅ | ✅ |
| 污染检出 | 对污染域名返回错误答案 | 查询内置污染样本域名，与直接问权威 NS（TCP 53）的答案比对；同一域名重复 3 次，其中 ≥2 次与权威不重叠、彼此一致、且 RTT < 20ms 才记 1 次命中（避免单次抖动误判），命中答案留作证据 | — | ✅ |
| 结果一致性 | 多次查询答案是否稳定 | 同域名查 3 次，出现私网 IP / 答案抖动则记异常（每个域名每类异常最多记一次） | — | ✅ |
| **DNSSEC 验证**（v1.1 新增） | 解析器是否真的验证签名 | ① 正向：`cloudflare.com`（已签名）带 DO 查询，看 AD 位与 RRSIG；② 反向：`dnssec-failed.org`（签名故意失效）应返回 SERVFAIL，返回答案即"声称验证但未验证"；反向域名不可达时跳过 | ✅ | ✅ |
| **NSID / CHAOS**（v1.1 新增） | anycast 节点身份与解析器版本 | EDNS0 NSID（RFC 5001）向根域请求节点标识；CH 类查询 `version.bind`/`hostname.bind`；多个端点返回同一 NSID → 标"NSID重复(可能代理)" | ✅ | ✅ |
| **双栈可用性**（v1.1 新增） | 是否正常应答 AAAA、v4/v6 孰快 | 对若干域名查 AAAA 统计失败率；同一服务器名同时有 v4/v6 端点时比较缓存 P50，差值 > ResolutionDelay(250ms, RFC 8305 §8) 才给出 v4/v6 倾向 | ✅ | ✅ |
| 同省率（就近性） | 解析结果落在同省 IP 的占比 | 解析大流量 CDN 域名（默认集 11 个：web 5 + video 3 + CDN 3，可配置；快速取前 8、完整最多 20），每域名 IP 子集按 `--seed` 确定性抽样（去偏 + 可复现），返回 IP 查离线归属库 | ✅ | ✅ |
| TCP 延迟中位数 | 对解析出的 IP 建立 TCP 443 连接的耗时 | 对抽样出的结果 IP 测一次 TCP 握手（不是 ping，避开 ICMP 限制）；同一 IP 只测一次 | ✅ | ✅ |
| HTTP TTFB | 带 Host/SNI 对该 IP 发 HEAD 请求的首字节时间 | 域名先稳定排序再按 `--seed` 抽样 topN（默认 5）；所有端点抽同一批，保证端点之间可比 | — | ✅ |
| ECS 支持 | 是否支持 EDNS Client Subnet | 携带本机公网 /24 的 ECS 与不携带各查一次，对比答案是否不同 | — | ✅ |

### 3.2 关键实现细节

**① 防缓存：随机子域名法测递归延迟**
公共解析器缓存是全局共享的，"第一次查"未必真递归。可靠做法是每轮生成随机前缀查询，如 `{uuid}.probe.baidu.com`——解析器必须走完"到权威服务器"的完整链路（权威返回 NXDOMAIN 同样测量到了递归路径），任何缓存都救不了，因此能真实反映其递归性能（涉及根、顶级域、权威的多级查询能力）。

**② 解析器回显（Echo）检测透明劫持**
部分宽带会对所有出站 53 端口流量做透明代理：你以为是问 8.8.8.8，实际是运营商解析器代答。利用 Google/清美的回显域名：

```
dig TXT o-o.myaddr.l.google.com @8.8.8.8
;; ANSWER: "xxx.xxx.xxx.xxx"   ← 实际代答的解析器 IP
```
回显 IP ≠ 8.8.8.8 → 存在透明劫持，UDP 53 的测速数据不可信，应提示用户改用 DoH/DoT。

**③ CDN 就近性是"适配宽带"的核心指标**
对每个候选 DNS 解析同一批域名（`www.baidu.com`、`www.qq.com`、`www.bilibili.com`、`v.qq.com`、`img.alicdn.com`、`www.douyin.com` 等，覆盖 web/视频/下载/图床多类 CDN）：
1. 返回 IP → 离线归属库查省/市，统计**同省率**；
2. 对返回 IP 逐个做 TCP 443 握手计时 → 得到**实际可达延迟**；
3. 完整模式加测 HTTPS HEAD TTFB（带正确 SNI，跳过证书校验仅用于探测）。

例：某境外 DNS 对 `www.qq.com` 返回了省外节点 → 同省率 40%、TCP 中位 35ms，即便它自身查询延迟 50ms 也会在总分中被就近性拖垮——这正是要暴露的问题。

**④ 测量公平性控制**
- 每个 DNS 的查询总量、域名集合、时序完全一致；
- 交叉轮询消除时间偏差；
- 每目标 DNS QPS ≤ 5，礼貌限速（重试同样走限速器）；
- 热身查询（默认 2 次）不计入统计，有效样本数由阈值控制（快速 8 / 完整 30）；
- 每域名 IP 子集与 TTFB 域名子集都按 `--seed` **确定性抽样**：既去掉"总取应答前几条/字典序靠前域名"的系统性偏好，又保证所有端点抽到同一批、同一 seed 下可复现；
- 网卡绑定：多网卡（宽带 PPPoE + WiFi）时允许 `--interface` 指定出口，测的就是这条宽带的路径。

**⑤ 环境自检（阶段 0）**
- 读取系统当前 DNS 作为"运营商/现有 DNS"基线候选；
- 检测 IPv6 可用性（决定是否纳入 AAAA/IPv6 DNS 测试）；
- **检测系统代理与 TUN/TAP 虚拟网卡**（如 tun 模式代理开着，所有测试结果都会失真）→ 打印醒目警告并建议关闭后重测。虚拟网卡判定不只看网卡名，还要求它**确实是默认路由的出口**（用一次公网拨号确认）：Tailscale 未开 exit node、Hyper-V/VMware/`vEthernet` 等虚拟网卡只要没抢默认路由，就只作普通提示、不判"不可信"，避免误报；
- 通过 STUN 或 `myip` 类接口获取公网 IP，供 ECS 测试使用。

**⑥ DNSSEC 验证判定（v1.1）**
只用"是否返回 RRSIG"无法区分"上游有签名"与"解析器真验证"。因此做**正反双向**：
- 正向：对已签名域名带 DO 位查询，`AD=1` 表示解析器声称验证过；只有 RRSIG 而 AD=0 属"上游有签名、解析器未验证"。
- 反向：对签名**故意失效**的 `dnssec-failed.org` 查询，真正验证的解析器必须 `SERVFAIL`；若照常返回答案，说明它并未真正校验。
两向合并成报告中"DNSSEC"列（验证 / 未验证）；反向域名不可达（本机被污染或网络受限）时只跳过反向，不据此判负。

**⑦ NSID / CHAOS 作为"同一解析器"的旁证（v1.1）**
NSID（RFC 5001）是 anycast 节点的身份标识。若两个不同名字的候选端点返回**同一 NSID**，极可能是同一个解析器/代理在代答（与透明劫持互为佐证），报告标注"NSID重复(可能代理)"。`version.bind`/`hostname.bind`（CH 类）多数公共 DNS 返回 REFUSED，取到值时作为补充证据。不支持 NSID/CHAOS 不计失败、不扣分。

**⑧ 双栈与 Happy Eyeballs 语境（v1.1）**
除记录解析器是否正常应答 AAAA（传输层失败率）外，对同一服务器的 v4/v6 端点比较缓存 P50：差值超过 ResolutionDelay（RFC 8305 §8 建议 250ms）才给出"倾向 v4 / 相当 / 倾向 v6"，避免把"没测到 IPv6"误当成"IPv4 更快"。

### 3.4 测量阈值与依据（集中配置，可审计）

所有测量相关的常量集中在配置的 `thresholds:` 段（`dnspick --list-thresholds` 打印本表，`--dump-config` 生成的模板内逐项带注释）。未写的项用内置默认；**写哪项覆盖哪项**（区分"没写"与"写了 0/false"）。

| 阈值 | 默认值 | 依据 |
|---|---|---|
| `qps` | 5 | 自我限速，避免被上游当成攻击源（RFC 4697 观察法；无强制值） |
| `timeout_ms` | 2000 | 公共 DNS 正常在亚秒级；2s 足以区分超时与高延迟（RFC 4697） |
| `rec_timeout_ms` | 3000 | 递归路径更长，需覆盖 NXDOMAIN 递归耗时（RFC 2308） |
| `retries` | 1 | 瞬时丢包不应直接判失败，但重试过多会掩盖丢包（RFC 4697 §4） |
| `warmup` | 2 | 丢弃首查的冷启动/连接建立样本 |
| `samples_fast` | 8 | 快速模式：足够估中位数，不足以准确估 P95 |
| `samples_full` | 30 | 完整模式：n≥30 时依中心极限定理可用正态近似估 P95 与 95%CI |
| `rec_rounds` | 5 | 随机子域名法每轮域名唯一，防缓存（RFC 4697） |
| `udp_buf_size` | 1232 | EDNS0 建议载荷，避免分片（RFC 6891 / DNS Flag Day 2020） |
| `pollution_rtt_ms` | 20 | 真递归不可能在 20ms 内完成，低于此值且答案不符即判污染 |
| `pollution_repeat` | 3 | 单次判定噪声大，需过半（≥2/3）重复命中才计一次污染 |
| `max_ips_per_domain` | 3 | 每域名抽样 IP 上限：控制时长并去掉「总取应答前几条」的偏好 |
| `ttfb_domains` | 5 | 每端点测 TTFB 的域名数（抽样而非取字典序前几名） |
| `cdn_fast` / `cdn_full` | 8 / 20 | 快速 / 完整模式的就近性域名数 |
| `consistency_domains` | 3 | 结果一致性检测的域名数 |
| `tcp_timeout_ms` | 3000 | CDN 边缘 TCP443 握手超时 |
| `doh_timeout_ms` | 6000 | DoH 走 HTTPS，需覆盖 TLS 握手（RFC 8484） |
| `resolution_delay_ms` | 250 | Happy Eyeballs ResolutionDelay（RFC 8305 §8） |
| `aux_probes` | true | 是否执行 DNSSEC / NSID / 双栈辅助探测（`--no-aux` 可关） |

## 4. 评分与推荐模型

### 4.1 归一化

各指标在**同一协议组内**做**比值归一**到 0~100：以本组最优者为 100 分，其余按比值折算（相对比较比绝对阈值更能回答"哪个最适合我"）。注意不是 min-max：最差者不会因为"是本组最慢"就被压到 0 分。

> v1.1 起基准与排名都在**协议组内**计算（udp / udp6 / doh / dot 各算各的）。原因：UDP 53 与 DoH 443、IPv4 与 IPv6 的路径与开销本就不同，混在一张表里比总分没有意义（§4.2）。

```
延迟分 L = 100 × (最快P50 / 本机P50)          # 缓存延迟 0.6 权重 + 递归延迟 0.4 权重
稳定分 S = 成功率 × 100
就近分 C = 同省率×60 + (100×最快TCP / 本机TCP)×40
干净分 P = 100 − NXDOMAIN劫持×40 − 透明劫持×30 − 污染检出×20/条 − 一致性异常×10
```

### 4.2 总分与推荐

```
总分 = 0.35×L + 0.20×S + 0.30×C + 0.15×P    （权重写入配置文件，可调）
```

推荐策略：
1. **主用** = 总分第一；若第一名干净分 < 100，优先在干净分满分者中取总分第一（安全优先）；
2. **备用** = 总分第二，且与主用分属不同运营商 AS（避免主备同生死）；
3. 运营商 DNS 即使总分不高，也单独展示一行"本地基线"结论（如"你的运营商 DNS 延迟最优但存在 NXDOMAIN 劫持"），方便用户权衡；
4. **没有任何成功测量的端点**（超时/不可达）记 0 分、标"无数据"、**不显示名次也不参与推荐**——"没测到"不等于"干净"，不能让空数据凭默认满分胜出。
5. **分组排名与分组推荐（v1.1）**：以上 1–4 条在**每个协议组内**独立执行——udp / udp6 / doh / dot 各出各的名次、各给各的主用/备用。报告按组分表，每组末尾一行"本组建议"；`--apply` 取 udp 组（无则 udp6 组）的主备写入系统。跨协议总分**刻意不可比**，不下全局名次。
6. **能力/质量披露不计分（v1.1）**：DNSSEC 验证、AAAA 异常、丢包率、NSID 重复等以"备注标记 + 报告列"呈现，**不进入加权总分**（保持四项权重之和恒为 1，新旧结果可比）。标记包括：`DNSSEC验证` / `DNSSEC未验证` / `AAAA异常` / `丢包x%`（首次尝试丢包率 > 5%）/ `NSID重复(可能代理)`。

## 5. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | **Go 1.22+** | 单二进制零依赖跨平台；goroutine 天然适合并发探测；备选 Python（dnspython）适合快速原型，但分发和并发不如 Go |
| DNS 协议库 | `github.com/miekg/dns` | 事实标准，UDP/TCP/DoT/EDNS 全支持 |
| DoH | 标准库 `net/http` + RFC 8484 wire-format | 无需额外依赖 |
| IP 归属库 | **ip2region**（离线 xdb，Apache-2.0 协议，~11MB，支持省市） | 离线运行不依赖在线 API；GeoLite2 对国内精度差，仅作补充 |
| 配置 | YAML（候选列表/域名列表/权重） | 用户可自行增删 |
| 输出 | `tablewriter` 终端表格；JSON/CSV 导出；HTML 报告（可选，v0.3） | — |
| 系统集成 | Windows: `Set-DnsClientServerAddress`；macOS: `networksetup`；Linux: 写 resolv.conf（提示 nmcli） | `--apply` 一键应用，默认 dry-run 打印命令 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 本机开着代理/TUN，全部结果失真 | 阶段 0 强制检测虚拟网卡与系统代理，检测到则红字警告并建议关闭重测；虚拟网卡还须**确实接管默认路由**才判负，避免 Tailscale（未开 exit node）/Hyper-V/VMware 等误报 |
| 运营商对 53 端口透明劫持，UDP 测速"测了个寂寞" | echo 回显检测识别，命中则在结果里标注"透明劫持(53被代理)" |
| 公共 DNS anycast 节点随时间调整，结论过期 | `--monitor` 周期复测；报告中标注测试时间，建议每月复测 |
| 测试高峰期网络抖动导致误判 | 交叉轮询 + 多轮统计（中位数/P95）+ 可信度标注（轮次不足时提示复测） |
| 高频查询触发公共 DNS 限流 | 全局限速 QPS≤5（重试同样走限速器） |
| Windows 防火墙首次运行弹窗 | 文档说明放行；TCP 探测仅出站连接，通常无需特殊权限 |
| `--apply` 误改系统配置 | `--apply` 默认只 dry-run 打印命令；真正写入要显式加 `--apply-force`，且先把当前 DNS 配置备份成 JSON（备份失败则中止，不改任何配置） |
| 完整模式样本量提升（30×）后总时长增加 | 抽样（每域名 IP 子集、TTFB 域名子集）控制探测规模；`--samples` 可按需下调；快速模式仍保持 8 样本 |
| 分组排名后"跨协议总分不可比"，用户可能误读 | 报告中每个协议组独立成表并各自给出"本组建议"；末尾口径说明明确"名次为协议组内排名，跨协议不可比"；CSV 首行注释与 `group` 列亦声明 |
| DNSSEC 反向判定依赖 `dnssec-failed.org` 可达性 | 反向域名不可达时只跳过反向，不据此判负；正向（AD/RRSIG）单独成立即可标注"验证" |
| NSID / CHAOS 多数公共 DNS 不开放或无返回 | 不支持 NSID/CHAOS **不计失败、不扣分**；仅在取到值时作为"同一解析器"旁证 |
| 统计口径改为 R-7 后历史数值不可直接对比 | R-7 更接近 numpy/Excel 定义、小样本估 P95 更稳；口径变更写入 §3.4 与报告口径说明，跨版本比较需以新口径重测 |
| CSV `rank` 语义由全局名次变为组内名次 | CSV 首行注释 `{"# rank 为协议组内排名；跨协议不可比"}`，并新增 `group` 列区分协议，消费脚本据此分组 |

## 附录 B：为什么不用 ping 测 DNS

1. 很多服务器/路径对 ICMP 限速或丢弃，结果不可信；
2. ping 延迟 ≠ 53 端口解析服务能力（排队、限流都在应用层）；
3. 本工具直接用"真实 DNS 查询的 RTT"作为延迟指标，测的就是用户将获得的体验。

## 附录 C：RFC 依据清单

| RFC / 规范 | 本工具用到的点 |
|---|---|
| RFC 1035 | DNS 报文与查询类型（A/AAAA/TXT/NS）基础 |

## 附录 D：统计口径定义

| 量 | 定义 | 说明 |
|---|---|---|
| 有效样本 n | 丢弃热身（默认 2）后的成功样本数（快速 8 / 完整 30，`--samples` 可覆盖） | 统计只基于有效样本 |
| R-7 分位数 | `h=(n-1)·p/100`，在 `⌊h⌋` 与 `⌈h⌉` 间线性插值 | 与 numpy / Excel `PERCENTILE.INC` 一致；偶样本中位数为两中值平均 |
| 样本标准差 s | 分母 `n-1`（无偏估计） | n<2 视为 0 |
| 95% CI 半宽 | `t(n-1,0.975)·s/√n`；`n-1>30` 用 1.96 近似 | 表示"均值"的不确定度，非单次延迟 |
| 丢包率 | 首次尝试即失败的查询数 / 总首次尝试数 | 重试成功仍记 1 次丢包，避免被重试掩盖 |
| 成功率 | 非超时、非丢包的查询占比 | 超时阈值 2s（完整递归 3s），重试 1 次 |
| 同省率 | 解析结果 IP 落在本省的占比（离线库 ip2region） | 每域名 IP 子集按 `--seed` 确定性抽样 |
| 抽样（`SampleSubset`） | 以 `--seed` 做确定性洗牌取前 k | 去偏（非"取应答前几条/字典序前几名"）+ 可复现（同 seed 同结果） |
